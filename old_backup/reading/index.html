Reading List

Reinforcement Learning

  1. Deep Reinforcement Learning for Dialog Generation [pdf]

    Jiwei Li et. al.

    > Brief Summary

    Seq2Seq models provides a neural generation model, that maximizes the probability of generating a response given previous dialog.

    This has two main issues:

    1. It uses MLE objective, which does not explicitly model the real world goals of a dialog.
    2. It has the tendency to generate conversation killing dialogues, which offers no way to continue conversation.

    There have been two major categories, in which we can categorize dialog generation.

    1. Machine Translation approach
    2. Task-oriented systems, for domain specific tasks.

    Present methods does not aim at solving the two above problems. To address these, the paper propose a RL based method. The method integrates Seq2Seq with RL, this providing framework for coherent dialog generation (MLE) with real world goals (RL).

    The system consists of two agents $(p, q)$ generating dialogues $p_1, q_1, p_2, q_2...p_i, q_i$. These are viewed as actions taken according to a policy, that is parametrized by the LSTM. They use policy gradient methods, instead of (the more popular) DQN, which enables use to MLE parameters from Seq2Seq (need to clarify by studying Seq2Seq and Policy Gradient methods in detail).

    The system:

    • STATE: consists of previous two dialogues $[p_i, q_i]$.
    • ACTIONS: a dialog $p_{i + 1}$ (infinite action space).
    • POLICY: $P(p_{i+1} | p_i, q_i)$ given by an LSTM.
    • REWARDS: This is where the paper tries to encode the real world goals.
      • r1: A reward that reduces the likelihood of generating dull response.
      • r2: A reward for providing new information
      • r3: Use LSTM language model to ensure coherency of the response.
    The final reward is a convex combination of these. The weights are fixed to 0.25, 0.25 and 0.5 for each reward respectively.

    The paper simulates dialog between two agents using the above model to learn the policy. For this they start with a policy that is learned in a supervised setting. They initialize the system using Seq2Seq and uses mutual information measure to calculate the reward at the end of sequence generation. Once initialized, policy gradient is used to maximize future reward. They also employ curriculum learning for training.

    They system is evaluated based on length of the dialog, its diversity, as well as human judgment.



  2. Neural Architecture Search With Reinforcement Learning [pdf]

    Barret Zoph, Quoc V. Le

    > Brief Summary

    Prior to the advent of deep learning, feature engineering used to be the single most significant task for designing a machine learning system. Now, the neural networks learn the representation on their own, sparing us the daunting task of designing features. But in the last few years, neural network architecture has been growing more and more complex, and it has in and of itself has become a challenge to design an architecture. Moreover, since the field is quite young, there is no concrete reference or reliable heuristics on could rely upon, to design a neural system. This paper promises a solution to this problem by presenting an architecture to learn architectures.

    The work is based on the simple observation that neural networks can be typically specified by a variable-length string (a lot like Lego blocks). It borrows ideas from a wide range of research areas, like: hyper-parameter optimization, neuro-evolution algorithms, program synthesis and inductive programming, end-to-end sequence to sequence learning, BLEU optimization in neural machine translation, and meta learning. The paper succinctly specifies how they draw from each of these fields.

    The paper proposes methods for generating a couple of things:

    1. Generate convolutional architectures
    2. Incorporate skip connections to the aforementioned architecture
    3. Generate architecture for recurrent cells

    The basic work-flow for generating a convolutional architecture is as follows:

    • A controller RNN generates sequence of hyper-parameters. This process stops at a threshold.
    • A neural network with above architecture is built and trained.
    • At convergence, the accuracy of the network, $R$, is measured on a validation set.
    • The parameters $\theta_c$ of the controller are optimized to maximize the expected accuracy.

    The process of optimizing $\theta_c$ is posed as a reinforcement learning problem, where we view the list of tokens generated by the controller as actions $a_{1:T}$, and the accuracy of the trained network $R$ as the reward. Since the reward is not differentiable, the authors use REINFORCE rule to learn the parameters.

    To add skip connections, they add anchor points to each layer. A layer N can then have up to $N-1$ connections sampled from a learned distribution.

    To generate recurrent cell architecture, they take inspiration from LSTM architecture. The structure of cell is specified as a tree of nodes, and the RNN controller learns to label the nodes with operations. The tree takes history and data as input. Inspired by LSTM, the also add cell state as input to the tree.

    A distributed training with asynchronous parameter updates is employed to speed up the training.

    The method is tested on CIFAR-10 (convolution) and Penn Treebank (recurrent). It can come up with architectures that produces results comparable to the state-of-art.



Natural Language Processing

  1. Snowball: Extracting Relations from Large Plain-Text Collections [pdf]

    Eugene Agichtein, Luis Gravano

    > Brief Summary

    SNOWBALL presents a bootstrapping strategies for generating patterns and extracting relations from text.

    It builds on DIPRE, an approach for extracting structured relations from HTML where the user provides the system with a handful of tuples, and some regular expression to match entities.

    SNOWBALL system has the following key components:

    An approach to generate patterns (a 5-tuple of form $\lt left,TAG1,mid,TAG2,right \gt$), that is both selective and has high coverage. For this, it defines a similarity measure $Match(t_p,T_s)$ and a threshold $\tau_{sim}$. A key improvement over DIPRE in generating patterns was to use NERs to match the tags. An approach to evaluate tuples, for which it defines the notion of confidence. The confidence is a function of selectivity and the number of patterns that generated it. A threshold ($\tau_{sup}$) based scheme then filters the tuples. This prevents bad tuples from being generated, and is responsible for most of the improvement over DIPRE. An evaluation metric to calculate the Precision and Recall over multiple documents. For this, it creates the Ideal set, which is supposed to contain all the tuples we can expect to find.

    Pros:

    • Bootstrapping allows the system to work on large data set with minimal user input.
    • Using NER to match patterns and confidence score to select good tuples were good improvements (for that time).
    Cons:
    • Evaluation of the system is not scalable. New relations will require lot of work to generate the Ideal.
    • The method is tested for plain text documents, and not for HTML.



  2. Never-Ending Learning [pdf]

    T. Mitchell et. al.

    > Brief Summary

    The paper proposes a paradigm of machine learning termed "Never Ending Learning" (also called Lifelong Machine Learning in modern parlance, and can be contrasted with Multi-task learning and transfer learning) and apply it to the task of language learning.

    The NEL problem is defined as an ordered pair of where L is a set of learning tasks and C is a coupling constraint, that specifies degree of satisfaction over two or more tasks. Given such a learning problem, the learning agent outputs a sequence of solutions to the task, maximizing the performance of each task, and the degree of constraint satisfaction.

    The paper applies the NEL paradigm to a system for language learning, called Never Ending Language Learning (NELL). The task is: 

    
                                Given:
                                - ontology defining catagories/relations
                                - few examples of each
                                - the web (a huge corpora)
                                Do 24 hours a day, forever:
                                - read (extract) beliefs from web, remove old beliefs, grow knowledge base
                                - learn to read better than previous day

    NELL learning tasks L include:

    • Category Classification
    • Relation Classification
    • Entity Resolution
    • Inference Rules

    ,and the coupling constraints C include: Multi-label mutual exclusion coupling Coupling relations to their argument types etc.

    The learning in NELL is an infinite loop, comparable to EM algorithm for semi-supervised learning.

    Likes:

    • One of the first attempts at continuous learning (lauded as exhibiting own "curiosity")
    • Ability to incorporate human feed-backs which is useful because overtime it accumulates erroneous facts (Internet cookies are baked goods).
    Dislikes:
    • No way to monitor its progress. This leads to spending time in saturated areas a lot more than it should.
    • Lack of reasoning power.


  3. Open Information Extraction: the Second Generation [pdf]

    Oren Etzioni et. al.

    > Brief Summary

    This paper presents an Open Information Extraction paradigm (improving over the original). Its goal is to "understand" text. The term "Open" refers to identifying unbounded relations. To this end, OpenIE avoids specific nouns and verbs in formulating the extractors.

    Open IE systems work in a 3 step manner: Label (distant supervision or heuristics) -> Learn (sequence labelling) -> Extract (use the learned model to extract relations (Arg1,Rel,Arg2).

    Previous OpenIE systems had 2 significant problems: incoherent extraction, and uninformative extractions.

    The paper presents an architecture named ReVerb. It employs two constraints: Syntactic - specifies what the relationship can be between, using syntactic representations, and Lexical - where to break an over-specified relation into smaller ones (based on heuristics on number of distinct arguments a relationship takes over the corpus).

    While the ReVerb addresses the issues mentioned, the other side of Open IE (as opposed to relations) is to identify proper arguments. For this the paper proposes ArgLearner, that learns to classify the boundaries of Arg1 and Arg2.

    The paper then combines the two models: $ReVerb+ArgLearner=R2A2$

    Likes:

    • Learns unbounded relations efficiently.
    Dislikes / Improvements:
    • Probably can't learn certain relation pattern, that does not fit the constraint's regular expression (which requires a V).
    • Like many other systems that relies on plurality, the heuristic for lexical constraint may miss (or over-simplify?) certain relations.



  4. A Shortest Path Dependency Kernel for Relation Extraction [pdf]

    Razvan C. Bunescu and Raymond J. Mooney

    > Brief Summary

    This paper proposes a method for extracting relations based on the hypothesis that the relationship between two entities in a sentence is almost exclusively captured by the shortest distance between the entities in an (undirected) dependency graph.

    Observations:

    • Unlike the OpenIE setting (web scale), the proposed method can afford to use representations from deeper end of the spectrum of representations (sentence -> PoS based regex -> dependency relations) as it is run on a relatively smaller data.
    • The paper uses both local dependencies (from CFG and CCG) and long distance dependencies (CCG). Contrary to expectations (yet, not uncommon in NLP) results show that shallower CFG produces better results. The authors note that this is due to the quality of the parser. It would be interesting to see how the system performs given current state of art parsers.
    • The use of parse trees have one start improvement over the other less deeper methods, and that is to handle long complex relations, and breaking them down to meaningful simple ones (as shown in figure 2).
    • There could be two directions one could think of extending this work. One is to make use of deeper semantic parsers like UNL (and be slower), or apply it to a much larger setting (~OpenIE) which currently uses basic PoS based extractors (and run for long time).
    • Finally, the basic assumption that the paper makes (mentioned in the first line), is itself very interesting. It seems to be an over-simplified assumption, yet quite valid for most regular language content. But while it performs admirably on the data set, it may fail in some situation (probably artificially created ones).
